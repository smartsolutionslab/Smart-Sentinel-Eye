## The option, and why the other two lose

### Option 2 — a dedicated `e2e/tsconfig.json` plus its own script

Chosen. Three reasons, in descending weight.

**1. The compilation units genuinely differ, and it is measured.** `apps/**` is
browser code: DOM lib, no Node types. `e2e/` is Node code whose `page.evaluate`
callbacks are browser code checked *in place* — so it needs **both**. The figure
that settles it: with `lib` reduced to `["ES2023"]` the suite reports **52**
errors instead of **7**. DOM is not optional for `e2e/`, and Node types are not
acceptable for `apps/**` (a spec file that reached for `process.env` in browser
code would compile). Two configs is what two different type environments look
like; it is not duplication.

**2. Option 1 cannot be done without moving `apps/**`.** Extending
`pnpm -r --filter "./apps/**"` to reach `e2e/` requires making `e2e/` a workspace
package (`pnpm-workspace.yaml` lists `apps/*` only) with its own `package.json`,
`tsconfig.json` and `typecheck` script — which *is* option 2, plus a package
manifest nobody needs. The cheaper reading of option 1 — add `@types/node` and a
root `tsconfig.json` covering everything — would put Node globals in scope for
`apps/**`, weakening a check that currently holds. **That is a gate weakened to
save a file, and it is refused.**

**3. Option 3 is refuted by evidence, not preference.** `playwright test --list`
exits 0 with `token.toFixed(2)` on a `string` and with `startsWithX` inside a
`page.evaluate` callback; `tsc` reports all three. The full counterfactual is in
`spec.md`. The issue's own argument — transpilation is not type-checking — is
correct, and now demonstrated rather than asserted.

### The globals trap, and how this plan avoids it

`apps/shared/eslint.config.js` pins **26 named globals** with `MediaStream`
present and `MediaStreamTrack` absent; #2108 worked around exactly that. The trap
is inheriting that list by accident.

**This plan cannot inherit it, because it touches no ESLint config at all.** The
typecheck's globals come from `lib` + `types` in `tsconfig`, which are TypeScript
mechanisms with no relationship to ESLint's `languageOptions.globals`. `lib: DOM`
is the *whole* DOM, so the `MediaStreamTrack`-shaped gap cannot exist on the
typecheck side. The trap is real and it is **entirely in the lint decision**,
which is why the lint decision is deferred rather than rushed — see *Scope*.

## Scope: typecheck yes, format yes, lint no

The issue's title says typecheck; its body names all three. Delivering one while
implying three, or three when the gate was one, are both failure modes. The
argument, per concern:

**Typecheck — in, as P1.** The issue's title, the named defect class, and the
whole of its "where it bites hardest" paragraph. Costs one config file, one
dependency, one script, one CI step edit, seven fixes.

**Format — in, as P2.** Prettier is already configured repo-wide
(`.prettierrc.json`, `.prettierignore`, `eslint-config-prettier` in all three
packages) and already runs in CI as `pnpm format:check`. Extending it to `e2e/` is
**one glob**, adds **no dependency, no config file and no globals question**, and
costs **3 reformatted files** — measured, not estimated. Leaving `e2e/` type-checked
but unformatted is a half-state with no defender. It is a separate *story* with its
own commit so the P1 diff stays readable, not a separate issue.

**Lint — out, and it is a new issue.** The cost profile is different in kind, not
degree:

- ESLint is **not a root dependency**. `node_modules/.bin/eslint` does not exist;
  it lives in each app's package. Linting `e2e/` means adding `eslint`,
  `@typescript-eslint/parser`, `@typescript-eslint/eslint-plugin` and
  `eslint-config-prettier` at the root — four packages, against `@types/node`'s
  one.
- It needs a **new root `eslint.config.js`**, and that file is where the globals
  allowlist decision has to be made: `e2e/` needs Playwright's Node globals *and*
  the browser globals its `evaluate` callbacks use. Getting that list wrong
  produces either false positives across 21 spec files or a silently permissive
  config — the #2108 failure mode, one layer up.
- Unlike the typecheck, **the error count is unmeasured**, because measuring it
  requires the config whose content is the open question.

Bundling an unmeasured, four-dependency, globals-sensitive change into a
seven-error config fix is how a clean slice becomes a repair job. **T009 files the
follow-up issue**, so "out of scope" is a recorded decision with an owner rather
than a silence.

## The configuration

### `e2e/tsconfig.json`

```json
{
  "extends": "../tsconfig.base.json",
  "compilerOptions": {
    "noEmit": true,
    "types": ["node"]
  },
  "include": ["**/*.ts"]
}
```

Four notes, each load-bearing:

- **`extends` the base**, so `e2e/` inherits the same strictness `apps/**` has —
  `strict`, `noUncheckedIndexedAccess`, `noImplicitAny`, `noUnusedLocals`. Four of
  the seven errors exist *because* of `noUncheckedIndexedAccess`. Relaxing it for
  `e2e/` would drop the count to 3 and would be a weakened gate; it is not done.
- **`lib` is inherited, not overridden.** `["ES2023","DOM","DOM.Iterable"]` is what
  makes `page.evaluate` callbacks checkable. Measured: overriding it to `["ES2023"]`
  yields 52 errors.
- **`types: ["node"]`** is the only addition. `@types/node@22` matches
  `engines.node` (`^22.22.2 || ...`) and the CI `setup-node` version.
- **`include: ["**/*.ts"]`** is a directory glob, not an enumeration — AS-4. It picks
  up `e2e/support/` and anything added later without a second edit.

`jsx` is left at the base's `react-jsx` and is inert: `e2e/` has **no `.tsx` file**
(0 of 32). Do not override it "for tidiness" — an override is a claim, and this one
would be untested.

### Root `package.json`

```json
"typecheck": "pnpm -r --filter \"./apps/**\" typecheck && pnpm typecheck:e2e",
"typecheck:e2e": "tsc -p e2e/tsconfig.json --noEmit",
"format": "prettier --write \"{apps,e2e}/**/*.{ts,tsx,js,jsx,json,css,md,yaml,yml}\"",
"format:check": "prettier --check \"{apps,e2e}/**/*.{ts,tsx,js,jsx,json,css,md,yaml,yml}\"",
```

The format globs are US2; the two typecheck lines are US1.

### `.github/workflows/ci.yml`

The `frontend` job's Typecheck step today **duplicates** the script body rather
than calling it:

```yaml
      - name: Typecheck
        run: pnpm -r --filter "./apps/**" typecheck
```

Change it to `run: pnpm typecheck`. This is a deliberate small widening of the
diff, and it is the *smaller* change of the two available: adding a second step
would leave two places that must both be edited whenever the typecheck scope
moves, which is the drift shape ADR-0139 exists to close. After the edit, CI and a
local `pnpm typecheck` check the same thing by construction.

**Do not** apply the same treatment to the Lint or Test steps. They are correct as
they stand, the drift risk is hypothetical there, and touching them is a drive-by.

## The seven fixes — shape, and what is forbidden

Every fix is a **guard or an annotation**. Reaching green by any of the following
is a review blocker, not a shortcut:

- `any`, explicit or implicit
- `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`
- a non-null assertion (`!`)
- a type assertion (`as T`) introduced to silence one of the seven
- relaxing any `compilerOptions` inherited from `tsconfig.base.json`

`e2e/` today has **zero** `any` and **zero** suppressions. That number must still
be zero after this change, and T007 checks it. A typecheck that passes because
everything is `any` is the entry #2141 is currently cataloguing; this spec must not
supply one.

| Error | Site | Fix |
|---|---|---|
| TS7034 / TS7005 | `kiosk-identity-herd.spec.ts:51` | Give `screens` a real element type derived from its producer — `const screens: Awaited<ReturnType<typeof screenUnderOutage>>[] = [];`, or a named `interface` if that reads better. One edit clears both reports. |
| TS18048 | `support/kiosk-session.ts:66` | The `[, claims]` destructure is **inside a `page.evaluate` callback** and runs in the browser: `expect` is not available there. Return `null` on absence, matching the two `return null` branches already above it, and let the existing `expect(payload, ...).not.toBeNull()` in the Node half report it. |
| TS2769 ×3 | `wall-authority:21`, `wall-outlives-its-session:30`, `wall-withdrawal:70` | Node context. `if (payload === undefined) throw new Error('<what was malformed>');` before `Buffer.from`. A thrown error inside a Playwright test fails it with that message. |
| TS2322 | `wall-withdrawal.spec.ts:88` | Replace `expect(issuer, 'a grant should name its issuer').toBeTruthy(); return issuer;` with `if (issuer === undefined) throw new Error('a grant should name its issuer');`. Same message, same failure, and it actually narrows. **Not** `return issuer!` and **not** `return issuer as string`. |

**Do not extract a shared JWT helper.** The three TS2769 sites are near-identical
decoders in three files, and the duplication is real — but consolidating them is a
refactor of e2e helpers whose only covering test is a booted Aspire stack, which
this slice explicitly does not run (constitution §Testing: a behaviour-preserving
change needs covering tests green before and after). Mixing it in would also make
this PR a config change *and* a refactor, against ADR-0036. Recorded in the
follow-up issue instead.

## Boundary rules

No cross-context reference is created or altered; no `src/` project is touched.
`NetArchTest` and the architecture test suite are unaffected. The one boundary this
change *does* respect is between compilation units: `apps/**` must not gain Node
globals, and the dedicated `e2e/tsconfig.json` is precisely what keeps that true.
